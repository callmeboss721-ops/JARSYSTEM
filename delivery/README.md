# JAGUAR SPK Delivery — ระบบสั่งเดลิเวอรีปิดของร้าน

ระบบสั่งอาหาร/เครื่องดื่มเดลิเวอรีผ่านไรเดอร์ประจำร้าน แยกจากระบบสะสมแต้มเดิมทุกส่วน

## ไฟล์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `index.html` | เว็บลูกค้า: ลงทะเบียน (ชื่อ/เบอร์/ที่อยู่/ปักหมุด), เลือกเมนูสไตล์ Grab, ตะกร้า, ชำระเงิน PromptPay QR หรือโอนเข้าบัญชี, ติดตามสถานะ + แผนที่ตำแหน่งไรเดอร์แบบสด |
| `rider.html` | แอปไรเดอร์ (เข้าสู่ระบบด้วยรหัสไรเดอร์): รับออเดอร์, อัปเดตสถานะ, เปิดแผนที่, โทรลูกค้า, แชร์ตำแหน่ง GPS สด, เส้นทางแนะนำเมื่อมีหลายออเดอร์, ส่งออเดอร์เข้ากลุ่มทันที |
| `dashboard.html` | แดชบอร์ดร้าน (รหัสผู้ดูแล): สถิติรวมวันนี้ (รายได้, จำนวนออเดอร์, สถานะ), ประวัติออเดอร์ครบทุกเหตุการณ์ สั่ง → ชำระ → รับ → ส่ง → ถึงมือ, กรองตามสถานะ/วันที่, ตั้งพิกัดร้านอัตโนมัติจาก GPS หรือกรอกเอง |
| `app.css` | ธีมพรีเมียมกลางตาม **JAGUAR SPK Brand ID 2026** (`#08120A`, `#0D1F10`, `#FFC400`, `#00A651`, `#A6FF00`) โหลดหลัง inline style ของทุกหน้า |
| `dt-notify.ts` | ซอร์สของ Edge Function `dt-notify` บน Supabase (ส่งออเดอร์เข้ากลุ่ม Telegram แบบ batch) |
| `security-upgrade.sql` | สคริปต์ SQL สำหรับรันใน Supabase SQL Editor เพื่อตรวจ `rider_pin` / `admin_pin` ผ่าน RPC `verify_dt_pin` ฝั่งเซิร์ฟเวอร์ (bcrypt hash + RLS ซ่อนแถว PIN จาก client) |

## การทำงานของระบบ

1. ลูกค้าลงทะเบียนครั้งเดียว (ชื่อ, เบอร์ 10 หลัก, ที่อยู่, ปักหมุด GPS) ข้อมูลเก็บในตาราง `dt_customers`
2. เลือกเมนูจาก `dt_menu_items` กดดูรายการ เลือกวิธีชำระ (PromptPay QR สร้างจากเลขพร้อมเพย์ใน `dt_settings` หรือโอนเข้าบัญชีที่ระบุ) กดยืนยันคำสั่งซื้อ
3. ออเดอร์บันทึกใน `dt_orders` สถานะ `new` (รอยืนยันการชำระเงิน)
4. ทุก 20 นาที `pg_cron` เรียก Edge Function `dt-notify` รวมออเดอร์ที่ยังไม่ส่งแล้วส่งเข้ากลุ่ม Telegram พร้อมลิงก์แผนที่ (หรือกด "ส่งเข้ากลุ่มทันที" จากหน้าไรเดอร์)
5. ไรเดอร์เข้าหน้า `rider.html` ใส่รหัสไรเดอร์ กดอัปเดตสถานะ: ยืนยันรับเงิน → รับออเดอร์ → เริ่มจัดส่ง → ส่งสำเร็จ
6. ลูกค้าเปิดหน้าเดิมแล้วใส่รหัสออเดอร์เพื่อดูสถานะ (อัปเดตทุก 10 วินาที)

## สถานะออเดอร์

`new` → `confirmed` → `pickup` → `delivering` → `done` (ยกเลิกได้ที่สถานะ `new` เท่านั้น)

## การตั้งค่าที่ต้องทำในตาราง `dt_settings` (แก้ผ่าน Supabase Dashboard)

| key | ความหมาย | ค่าเริ่มต้น |
| --- | --- | --- |
| `promptpay_id` | เลขพร้อมเพย์ (เบอร์โทร 10 หลัก หรือเลขนิติบุคคล) | ยังไม่ระบุ |
| `bank_name` | ชื่อธนาคาร | ยังไม่ระบุ |
| `bank_account_number` | เลขบัญชี | ยังไม่ระบุ |
| `bank_account_name` | ชื่อบัญชี | ยังไม่ระบุ |
| `delivery_fee` | ค่าจัดส่ง (บาท) | 0 |
| `rider_pin` | รหัสเข้าหน้าไรเดอร์ | 2580 (ควรเปลี่ยน) |
| `shop_name` | ชื่อร้าน | JAGUAR SPK Delivery |

## การเปิดใช้แจ้งเตือนเข้า LINE ร้าน / กลุ่มไรเดอร์ (LINE Messaging API)

1. สร้าง Messaging API Channel ใน LINE Developers รับ `LINE_CHANNEL_ACCESS_TOKEN`
2. เชิญบอทเข้ากลุ่มร้าน/ไรเดอร์ แล้วนำ `User ID` หรือ `Group ID` มาตั้งเป็น `LINE_TARGET_ID`
3. ตั้ง secrets ใน Supabase: `supabase secrets set LINE_CHANNEL_ACCESS_TOKEN=xxx LINE_TARGET_ID=xxx`
4. เมื่อลูกค้ากดสั่งซื้อ ระบบจะเรียก `dt-notify` ส่งรายละเอียดออเดอร์ + ลิงก์ Google Maps เข้า LINE ทันที (และยังมีปุ่มกดส่งเข้า LINE ด้วยตนเองในหน้าติดตามออเดอร์ด้วย)

## การเปิดใช้ Telegram (ทางเลือกเพิ่มเติม)

1. คุยกับ `@BotFather` ในแอป Telegram สร้างบอท รับ `TELEGRAM_BOT_TOKEN`
2. เชิญบอทเข้ากลุ่มไรเดอร์/ร้าน แล้วหา `TELEGRAM_CHAT_ID`
3. ตั้ง secrets ใน Supabase: `supabase secrets set TELEGRAM_BOT_TOKEN=xxx TELEGRAM_CHAT_ID=xxx`
4. รอบ cron ถัดไป (หรือกดปุ่มส่งทันทีในหน้าไรเดอร์) ออเดอร์ค้างจะถูกส่งทั้งหมด

## ข้อจำกัดที่ตั้งใจไว้

- ระบบนี้แยกจากระบบสะสมแต้ม SPK เดิมทุกตาราง (dt_ prefix) ไม่แตะ routes, การเข้าสู่ระบบ, ข้อมูลสมาชิกเดิม หรือกติกาคะแนน
- การยืนยันการชำระเงินเป็นแบบมนุษย์ตรวจสลิป (ร้านกดยืนยันในหน้าไรเดอร์) ไม่มีการเชื่อมระบบธนาคารอัตโนมัติ
- หน้าไรเดอร์ใช้รหัสแบบง่าย (ไม่ใช่บัญชีผู้ใช้เต็มรูปแบบ) เหมาะกับทีมไรเดอร์ประจำร้านขนาดเล็ก
- ตามกฎหมายไทย (พ.ร.บ.ควบคุมผลิตภัณฑ์ยาสูบ) ห้ามขายบุหรี่ทางออนไลน์ จึงไม่ใส่บุหรี่ในเมนูสั่งออนไลน์ — จำหน่ายหน้าร้านเท่านั้น
